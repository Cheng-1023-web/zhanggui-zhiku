# 运维手册

## 日常巡检

每日巡检项包括：检索服务健康度（/api/stats 返回 200 且延迟 P95 < 2s）、向量索引与文档数量一致性、图数据库连接状态、磁盘剩余空间（阈值 20%）。巡检脚本位于 `scripts/healthcheck.sh`，可接入企业监控平台。

## 检索延迟升高排查

检索延迟升高的常见原因按发生频率排序：第一，向量索引未随文档增量重建，导致索引碎片化，可通过重新执行 ingest 流程解决；第二，BM25 语料统计过期，同样需要重建索引；第三，重排序模型所在推理节点负载过高，检查 GPU 利用率并扩容推理副本；第四，图数据库慢查询，检查 Neo4j 的实体索引是否缺失。排查入口为「监控面板 → 检索链路追踪」，每条请求会输出召回、融合、重排各阶段的耗时分解。

## 索引重建流程

索引重建的标准流程：先对当前索引目录做快照备份；再执行全量 ingest 构建新索引；使用评测脚本对比新旧索引的 Recall@5 指标，确认无回退后切换服务指向新索引；最后保留旧索引 7 天再清理。整个流程预计 10-30 分钟，期间问答服务不中断（双索引热切换）。
